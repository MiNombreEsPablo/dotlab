# AGENTS.md

Web app for cheap thermal label printers; the web UI is the product. First target: the ORGBRO T003.

## Commands

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'               # [dev] = pytest
python src/dotlab/web/dev_server.py          # the web UI at http://localhost:8000 (Web Bluetooth needs localhost or https)
.venv/bin/pytest                              # tests (no printer needed)
```

## Scope (read before adding anything)

This is a hobby app: a fun, Y2K-flavoured label studio for cheap thermal printers (see README, "What this is"). A change
should be **fun**, or **small and useful**. Roadmap items carry tags (`fun`, `useful`, `polish`, `infra`, `research`,
`big`); prefer `fun` and `polish`, treat `big` as "only if it's fun to build and cheap to keep working", and don't start
`infra` items (new platforms, PyPI) unless someone asks. Don't grow the build or CI further: it was scaled back on
purpose. Put creative effort into the *labels* (effects, stickers, frames, fonts) before the app's own chrome.

## Compatibility (keep these true)

- **Python 3.9+.** No 3.10-only syntax in `src` (`from __future__ import annotations` everywhere; no `match`, no `zip(strict=)`, no `tomllib` in code or tests). CI runs the oldest (3.9, with the oldest libraries) and newest (3.13) Python on Linux only; the versions in between and other operating systems are not tested.
- **The engine is toolkit-free.** `core`, `render`, `imaging`, `composition`, `presets`, `api`, `protocol` never import a window toolkit or a transport; the browser runs them in Pyodide (`ENGINE_MODULES` in `web/dev_server.py` lists exactly what is shipped, and `tests/test_web.py` fails if `api` imports anything else). There is no CLI and no desktop app (both were removed on purpose).
- **Lower bounds are tested**: CI's Python 3.9 job installs Pillow 9.1.0, qrcode 7.4, fontTools 4.30. Raise a bound in `pyproject.toml` only together with that job.
- **A wheel needs every data file in `package-data`** (fonts, licences, `assets/*`); an editable install hides a missing one. `test_package_data_covers_every_asset_and_font` guards this.


## Layout

- `src/dotlab/spec.py` — `LabelSpec` dataclass (everything a label can be) plus geometry constants and the allowed choices (`EFFECTS`, `BACKGROUNDS`, `BORDER_STYLES`, …). Presets are `asdict(LabelSpec)`, so new fields must have defaults.
- `src/dotlab/layers.py` — **layers**: `LabelSpec.layers` is JSON text, bottom to top, of `Layer`s (`text`, `image`, `qr`, `sticker`), each with a box (`x`, `y` = top-left, `w`, `h`) and the properties of its type; only non-defaults are written. `parse` is lenient and cached (unknown types dropped, fractional numbers rounded, a box clamped to the label, `MAX_LAYERS` 48 = what an old label could hold; a `layers` text with no valid layer counts as none, so the old fields draw); a sticker's box is derived from its name and `scale`. **Rotate and flip:** every layer has `rot` (clockwise quarter turns: 0/90/180/270, anything else is rounded), `mirror` and `flip`; the box (`x`, `y`, `w`, `h`) is the layer as it lies on the label, so for 90/270 `render` lays the content out at (h, w) and turns it (`render._turn`/`_orient`: exact transposes, no resampling; text is laid out in its own frame, so `align`/`valign` are in the text's frame). A picture does mirror/flip inside `imaging.process`, before dithering, as it always did. **Transparent PNGs:** a picture layer is pasted through `imaging.process_mask` (the file's alpha at 50 %, fitted, mirrored and flipped like the picture, then turned with it; None when the file has no transparency), so see-through parts keep the Paper and the layers below instead of printing a white box; the old fixed fields (`legacy_layers`) go through the same path. **Remove background:** `Layer.cutout` (0 = off, 1-100 = tolerance, a slider like Pixelate) adds the picture's flat background to that mask: `imaging._flat_background` takes the commonest tone along the fitted picture's edge and clears what is within tolerance of it *and reachable from the edge* (the hole in an "O" stays); it works on gray, so a coloured background next to a subject of the same brightness is not told apart. The web inspector's Rotate (button and dropdown) turns the box about its centre and keeps it inside the frame. Free-angle rotation was left out on purpose: a 1-bit dot grid only stays crisp in quarter turns. `render._compose_layers` draws background → layers, with the frame (hazard bars and border) drawn just before the first sticker layer (or after the last layer): over pictures, QR codes and text, under stickers, which is what the old fixed arrangement did; text gets a white halo over a background pattern or a `cover` picture below it. **Old labels:** the fields before layers (`spec.LEGACY`: text, qr, image_*, font…, stickers) are still on `LabelSpec` and still render when `layers` is empty, but no client has controls for them: `render.migrate` / `api.migrate` turns such a label into layers (`legacy_layers` reproduces the old fixed arrangement pixel for pixel, tested in `tests/test_layers.py`; "Image only" printed just the picture, so its text and QR code come along as hidden layers, and the frame, which that layout skipped, is drawn; a QR string too long to draw still migrates and says so when drawn). The web page migrates a loaded preset, the remembered label and a label file (`api.composition_loads`). Label files embed each picture once (`layer_images`; a layer's path becomes the token `embedded:N`; a picture whose file is gone is blanked; `VERSION` 2); once a label has layers the legacy `stickers` field is ignored. The inspector's controls per layer type are data: `form.LAYER_FIELDS`, shipped as `options()["form"]["layer_fields"]` (a new `Layer` property must be added there or `tests/test_form.py` fails); the Paper (background, border, bars) is `form.FIELDS` with tab `PAPER`. A new layer starts inside the Paper's frame (`options()['geometry']` has `bar_height` and `border_insets`), and changing the border or bars moves the layers that fill the old usable area (`paperChanged`). `web/layers.js` is the list, the inspector and the selection box on the preview (smallest layer under the pointer wins, so a full-label text box doesn't hide a QR code on it).
- `src/dotlab/render.py` — toolkit-free drawing: fonts via fontconfig (`font_path` resolves family→file; variable fonts load at their default weight so `_apply_weight` sets the weight axis for the bold toggle; `list_font_families` feeds the GUI picker), auto-fit text layers (shadow/outline/3D/glitch/neon/scanlines, synthetic italic), backgrounds (cached, seeded RNG so they are stable), borders, hazard bars, QR. Effect parameters scale with font size; glitch drops its fringe/gaps below ~24/30 dots because small text turns to mush. Text is positioned by measured ink bounds, not Pillow's bbox (side-bearings). Lines are laid out by `_layout` with a fixed pitch — never use `multiline_text` with `stroke_width`: Pillow widens the pitch by 2×stroke per line, so stroked passes (outline/3D/neon/halo) drift off the unstroked fill on lines 2+ (regression test in tests/test_render.py). Over a background pattern text gets a white halo. Nothing may be drawn below `SH` (tests enforce it).
- `src/dotlab/fonts.py` + `fonts/` — the **bundled** OFL fonts (26 families incl. DejaVu, ~20 MB, licences in `fonts/LICENSES/`), grouped by category for the GUI. `font_path` prefers these over fontconfig, so labels print identically on any machine. To add one: put the .ttf and its `LICENSE.<slug>` in `fonts/`, add a `BundledFont` entry; `tests/test_fonts.py` checks files, licence, coverage flag and Japanese support.
- **Japanese:** none of the Latin display fonts have kana/kanji. `render._FontSet` picks a font per glyph (cmap via fontTools): the primary font if it covers the character, else the bundled `Zen Kaku Gothic New` fallback; text is split into runs sharing one baseline (anchor `ls`). Fonts flagged `ja=True` cover Japanese in their own style (DotGothic16, Yusei Magic, Dela Gothic One, Stick, Zen Kaku). Any new bundled font must still print Japanese (test enforces).
- `src/dotlab/core.py` — the one import for tests: re-exports spec/render/protocol names and `export_png`.
- `src/dotlab/protocol.py` — USB-free and toolkit-free: `tspl(spec)` (the one place the TSPL payload is built), `STATUS_QUERY`, `STATUS_FLAGS`, `status_problems`. Any transport (USB now; Bluetooth, the web build) sends these bytes.
- `src/dotlab/bluetooth.py` — constants only, no code: the BLE UUIDs, the Serial Port service, chunk sizes and gaps that the web client reads from `api.options()["bluetooth"]`, so every timing lives in one place and nothing about the printer is repeated in JavaScript.
- `src/dotlab/form.py` — the label's simple controls as data (`FIELDS`, `TABS`, shipped to clients in `api.options()["form"]`; `src/dotlab/web/form.js` renders them). **A new `LabelSpec` field must be added here or to `PENDING`, or `tests/test_form.py` fails**: that is what keeps every client's controls in step. A background/effect/border added in `spec.py` needs nothing here.
- `src/dotlab/api.py` — the client-neutral surface the web build drives : `label_from_json`, `preview_pixels` (W×H bytes, 0/255), `tspl_bytes`, `fonts_needed` (which bundled font files a label can open, for lazy loading), `options` (JSON of every choice, the geometry and the fonts, so a client builds its controls from it). Plain data in and out, no Pillow objects. Keep it that way: it is what keeps "one UI for both" possible later. `tests/test_api.py` checks it imports without Qt or USB.
- `src/dotlab/imaging.py` — toolkit-free picture pipeline for image labels: load (EXIF-upright, transparency over white) -> fit -> tone (gamma, brightness, contrast) -> dither. `load_gray` caches the decoded photo per (path, mtime, size) because decoding was ~70 of ~85 ms and the preview re-renders on every slider step (now ~13 ms); the cached image is shared, so never modify it in place. Default Floyd–Steinberg is left to `to_bitmap`; ordered (Bayer 4×4/8×8, built with Pillow ops, no numpy) and the hard cutoff produce pure 0/255 here, which `to_bitmap` passes through untouched. `LabelSpec.threshold` (not None) means hard cutoff and wins over `dither`; the Image tab maps that onto one combo. Looks (`mirror`, `flip`, `invert`, `pixelate`): with `pixelate` the tone and dither run at the low resolution and the dots are then enlarged (nearest), so the dither pattern itself is chunky; this is why `_dither(final=False)` forces Floyd–Steinberg early. `ImagePanel` dims itself until an image is chosen and hides the Cutoff row unless the hard cutoff is selected (keeps the tab, and so the window, short).
- **Image + text** (`LabelSpec.image_layout`, `image_size`): `"only"` (default) keeps the old behaviour (the picture replaces text/QR, `render` returns early). `left/right/top/bottom` carve `image_size` % (clamped 20-80) of the usable area out of `ax0/ax1/ay0/ay1` before the QR and text lay out in what is left, so QR and text need no special cases. `behind` pastes the picture covering the whole sticker (`ImageOps.fit`) and turns on the same white text halo that backgrounds get (the `backdrop` flag); it replaces the background pattern. Controls live on the Content tab (shortest page, so the window doesn't grow); the combo uses `AdjustToMinimumContentsLength` because a long item widens the whole window.
- **Text layout is pinned to Pillow's BASIC engine** (`render._font`, `layout_engine=ImageFont.Layout.BASIC`). Raqm, when the Pillow build has it, kerns differently and draws some fonts heavier, so labels depended on each machine's Pillow, and Pyodide's Pillow (the web build) has no Raqm. With the pin the desktop matches Pyodide dot for dot for 85 of 93 test labels; the rest (Orbitron, Pixelify Sans, Bungee, Monoton) differ by ~1 dot of glyph position because FreeType 2.15 (native Pillow 13) and 2.13 (Pyodide) rasterise slightly differently, which we can't control. Don't remove the pin.
- **Text is binarised** (`render._BINARY`, a 50 % threshold on the text layer's value and alpha): anti-aliased edge pixels used to go through the label-wide Floyd–Steinberg pass and came out as speckle. Measured across fonts/sizes it keeps ~97 % of the ink (a lower threshold thins small light text); `test_text_is_pure_black_and_white_before_dithering` checks every effect. Don't reintroduce gray in text layers.
- **Doodles** (`LabelSpec.doodle`, `doodle.py`, the Doodle tab): freehand ink is a 384×224 1-bit mask stored in the spec as base64 PNG text (empty = none), so presets and label files carry it with no extra plumbing. `render` draws it last, over picture/QR/text alike (`render` = `_compose` + the ink), so it works with every layout. `doodle.decode` is cached (the mask is shared: never modify it) and returns None for anything damaged or not exactly W×SH. The web canvas is one dot per pixel with hard-edged strokes (no anti-aliasing: the printer is 1-bit). Tools: round/square/calligraphy brushes, spray can (a timer while the button is down), line/rectangle/ellipse, paint bucket, (stickers are layers now, placed from the Layers tab; the Sticker tool and the raster engine's sticker objects are gone; while the Doodle tab is open the engine renders the label without `doodle`), eraser; `ink` paints with a dither tile instead of solid black: 18 of them in `doodle.INKS`, 4×4 or 8×8 (the engine reads the tile's own size; the tiles come from rules in `doodle._tile`, and `render.TILE_BACKGROUNDS` reuses six of them as label backgrounds (TV static is real random noise, `render._static`: an 8×8 tile showed its repeat), so a new tile is a background for one line). `fbox`/`foval` fill with the pattern inside a solid outline; Shift (`Doodle.constrain`, read from every pointer event) makes lines 0/45/90° and shapes square; "Snap to grid" (`showGrid`, `GRID` = 8 dots) draws faint crosses on the overlay (never printed) and snaps every pointer position. The old Qt hatch brushes were not used: they are too sparse for the bucket to see an outline as closed. The bucket floods with `ImageDraw.floodfill` on a wall mask = ink + the label's own dark pixels (the underlay), walls dilated 1 dot so pattern-inked outlines are closed, and the fill is grown back 1 dot to meet them. **You draw on the preview itself, not on a separate pad:** `DoodleCanvas` is a transparent child of the preview label (`MainWindow._place_canvas` lays it over the sticker part, visible only while the Doodle tab is open), `zoom` (= `PREVIEW_SCALE`) times the label's dots, and it paints only the ink (in the theme's tint). While that tab is open the preview below it is the label *without* its doodle, so a stroke changes nothing underneath and needs no re-render; leaving the tab renders the exact printed label again. (Rendering the ink into the preview would have dithered it together with the picture; this way the one approximation is confined to the drawing tab.) The canvas hands its pen strokes to a 1:1 ink image, emits `changed` only when a stroke ends, keeps 30 undo steps, and gets the label from `set_underlay` for the bucket. The panel shows only the controls the chosen tool uses. The tab bar was tightened (padding 11 px) to fit five tabs; a test checks every theme.
- `src/dotlab/stickers.py` + `sticker_tiles.py` — the stickers, 1-bit and enlarged 1-9× with nearest-neighbour, no image files to ship. Two sources: nine shapes drawn in code on a 24×24 grid (`_DRAWN`: the ones Kenney has no equivalent for, such as star, sun, moon, "fragile", "this side up") and 70 16×16 tiles cut from **Kenney's 1-Bit Pack 1.2 (CC0)**, held as rows of "0"/"1" in `sticker_tiles.TILES` (each with its sheet column,row; the licence text is `assets/LICENSE.kenney-1-bit-pack.txt`, a test checks it ships). `stickers.size(name)` is a sticker's side (16 or 24); nothing may assume 24. A placed sticker is an object, not ink: `LabelSpec.stickers` holds JSON text `[[name, centre x, centre y, scale], ...]` (`stickers.parse` validates leniently: unknown names/bad entries dropped, scale clamped to `MAX_SCALE` 9, at most `MAX_PLACED` 40; `canonical`/`encode` write it back), and `render` draws them (`stickers.layer`, cut at the sticker's edges) under the doodle ink, so they can still be selected, moved, resized and deleted. The picker shows them in themed `GROUPS` (every sticker in exactly one: a test checks; the page gets `options()['sticker_groups']`). To add a sticker: a tile in `sticker_tiles.py` (or a drawer in `_DRAWN`) and a place in `GROUPS`; look at it at 4× (a contact sheet is the quickest check). Keep any new third-party art CC0/public domain/permissive and ship its licence in `assets/`.
- `src/dotlab/composition.py` — label files: the label as it prints (a 1-bit PNG any viewer opens) with the design as JSON in a compressed `dotlab` text chunk (`format`, `version`, `spec`, optional embedded `image`), so Dotlab can reopen and edit it; an editor that drops the chunk leaves a plain picture. Unlike presets (config-dir store, path only) it embeds its image so it travels; embedded names are sanitised and stored under a content-hash name in a temp folder. Unknown fields ignored, a newer `version` refused. `MAX_TEXT_CHUNK` is raised for photos. Clients hand the engine the file's *bytes* (the browser worker writes them to Pyodide's FS and passes the path). Dropping a PNG on the page tries it as a label first, then as a picture.
- `src/dotlab/about.py` — the repo and issues URLs the About box links to. The version lives ONLY in `dotlab.__version__` (pyproject reads it dynamically).
- `src/dotlab/presets.py` — the rule for a preset's name (`clean_name`); the presets themselves live in the browser (`web/presets/local.js`).
- `src/dotlab/assets/` — the logo, all drawn by `tools/make_icons.py` (run it to regenerate; 1-bit pixel art, enlarged by whole numbers only): `icon-mark.svg` is the banner's mark (the page paints it in the look's text colour with a CSS mask), `favicon-16/32.png` the same mark on a white plate, `icon-192/512.png` the full tile (printer in front of the Synthwave sun and grid; kept inside the circle a maskable icon keeps) for the install icons, `icon-256.png` the README's.

## Web UI (direction: one UI for every client; WIP on the `web-ui` branch)

The product is a web UI (plain HTML/JS, ES modules, **no build step, no framework**) published on GitHub Pages, with the Python engine running behind it in the browser (Pyodide). There are no desktop builds or installers (they were removed on purpose; `git log` has them): a user opens the page. The old Qt UI and the CLI are gone too. Engine features (an effect, a font, a background) live in Python and reach every client for free.

- **The look is data**: `src/dotlab/web/themes.css` holds every colour, bevel, radius, font and banner detail as tokens, one block per look (Y2K Blue is `:root`; Pink overrides colours only; Gunmetal, Handheld and Plain (key `system`) define every token so nothing leaks in), chosen by `data-theme` on `<html>` (`src/dotlab/web/themes.js`; the picker is under the Print bar and is remembered through the store seam). `src/dotlab/web/style.css` only says where tokens go. **No look follows the OS dark mode** (a test checks): the page looks the same everywhere. **Never write a colour in a `style.css` rule** (a test fails) and give any new token to every look (a test fails). Keep the gel/LED/bezel vocabulary for new controls. The tone: modern structure, Y2K surface, small touches only (`--glow` round the preview, `--power-on` once at load, an empty-state note on the blank preview); Handheld and Plain have none of the motion or glow, and `prefers-reduced-motion` stops the animation. Tokens holding a `border-color` list take one colour (flat) or four (a bevel). Handheld tints the preview and the doodle ink (`--preview-ink` / `--preview-paper`, read back by `themes.js`). Contrast was computed for every look (see `docs/web-port.md`); re-check when a palette changes. The palettes came from `src/dotlab/theme.py`, which goes away with Qt.
- **The doodle**: `src/dotlab/web/doodle-raster.js` is the drawing engine (pure functions on a 384×224 bit grid; `node --test src/dotlab/web/test/*.test.js`, wrapped by `tests/test_web_js.py`, which skips without Node 22+); `src/dotlab/web/doodle.js` is the toolbar and the overlay canvas laid over the preview. While the Doodle tab is open the engine renders the label *without* its doodle and the overlay shows the ink (so drawing never waits on Python); elsewhere the engine draws the doodle into the preview. The tools, inks, limits and sticker bitmaps come from `doodle.describe()` and `api.options()`, and `tests/test_doodle.py` fails if they drift from the Qt canvas. Undo and redo are per stroke, `undoLimit` deep (30); a new stroke drops the redo history, and a fill that changes nothing leaves both alone.
- **Files**: a fourth seam, `files` (`files/browser.js`: a download and the Clipboard API). The label as an image is `api.export_png(spec, scale)` (sizes in `spec.EXPORT_SCALES`, names from `spec.file_stem`; the page's two export sizes). A label file is `api.composition_dumps` / `composition_loads` (`composition.py`; it re-encodes the doodle compactly), saved through the same seam; opening uses a file input. Opening a label must leave the very next render correct: a control that decodes asynchronously (the doodle) takes the loaded *text* at once and decodes only for display.
- **Presets** are a fifth seam, `presets` (`presets/local.js`: browser storage). `api.preset_entry` decides what is kept (the label without its picture, the doodle compact) and cleans the name (`presets.clean_name`). `presets.py` must import from `spec`, not `core`: the browser engine can't have USB.
- **The current label is remembered** (`main.js` `remember`/`rememberNow`: `store` key `label`, saved 500 ms after each render and on `pagehide`, restored before the first render). The picture is NOT kept: `image_path` is a path in Pyodide's memory, so it is stored empty and `hadPicture` makes the page say so. File → New label has no shortcut (browsers keep Ctrl+N).
- **Menus**: `src/dotlab/web/menus.js` is an ARIA menu bar plus the shortcuts its items name (`display: true` = shown but handled by the browser). Every item calls a named action in `main.js` that a button also calls (`copyImage`, `saveLabel`, `print`, ...), so behaviour lives in one place; items that can't act are disabled only when there is nothing to do (Clear image / Clear doodle): actions with nothing to work on say so ("Nothing to print.") the same way from a button, a menu item and a key. The About box facts come from `api.options()["app"]`; links go through `files.openLink`. Keep the controls before the preview in `index.html`: the grid places them, and Tab must follow the reading order. Give every new control an accessible name.
- **Font preview**: `web/fontpreview.js` replaces the Font `<select>`'s list with our own button + list so every name shows in its own face (browsers ignore per-option fonts in a native list: Firefox on Linux, macOS, iOS). The real `<select>` stays, hidden, as the source of truth: `form.js` still reads and sets it and listens to its `input` event. The `@font-face` rules are added and fetched on the button's first hover/focus/click (the Japanese fonts are 2-3 MB each), from `api.options()["fonts"]`.
- **Publishing**: `python src/dotlab/web/build_site.py OUT` writes the static site (the dev server's layout as files; the pinned `qrcode` wheel is hosted and hash-checked, Pyodide comes from the CDN at `dev_server.PYODIDE`). `.github/workflows/pages.yml` builds it on every change and deploys from `main` only when the repo variable `PAGES_ENABLED` is `true` (Pages source must be "GitHub Actions"). `src/dotlab/web/sw.js` is the service worker: Pyodide (CDN, one version per build), fonts and the qrcode wheel are cache-first (their URLs never change content); the page, the engine's `.py` files and the manifest are network-first with `cache: no-cache`, so an update is never mixed with old files; the cache is only the offline fallback. Responses must be cloned *before* they are returned (a late clone throws and silently caches nothing). Change `CACHE` if the rules change. Measured on a fast connection: repeat visits ~2.8 s vs ~3.2-4.3 s cold, because Pyodide start-up, not download, dominates; the gain is on slow networks and offline. Never start a URL in the page with a slash (the site lives under a project path; a test checks). The `web-parity` CI job (`tests/test_web_parity.py` + `src/dotlab/web/test/parity.mjs`) renders a fixed set of labels in Pyodide and natively and compares the dots: a new effect/border/background is covered automatically; if it fails on a label that is genuinely FreeType/Pillow-version dependent, leave that label out and say why in the test's docstring.
- Image dithers (`imaging._dither`): Floyd–Steinberg is left to `to_bitmap`; Atkinson (`imaging.atkinson_dither`, integer error diffusion, 3/4 of the error passed on, cached) and Bayer are applied to the picture and are pure black/white afterwards.
- `src/dotlab/web/main.js` + `form.js` + `index.html` + `style.css` — the UI, written once. It only talks to three seams, so a client can be swapped without touching it: **engine** (`options()`, `preview(spec)` -> `{pixels, hints}`), **printer** (`modes`, `print(spec, {mode, address})` -> `{problems, error}`) and **store** (`get`/`set`, `store/local.js`). Fonts a render opens must be in `api.fonts_needed` (a test records the real ones): the browser only has what it fetched, and a missing file silently falls back to another face.
- `src/dotlab/web/dev_server.py` serves `web/` plus `/engine/*.py` (only `ENGINE_MODULES`, straight from `src/dotlab`), `/engine/manifest.json` and `/fonts/*`, which is the layout a published site will have. `tests/test_web.py` fails if `api` starts importing a module the browser doesn't download. Browser adapters: `engine/pyodide.js` + `engine/worker.js` (Pyodide in a worker running the same `dotlab.api`; fonts fetched on demand through `api.fonts_needed`) and `printer/ble.js` (Web Bluetooth, constants from `api.options()["bluetooth"]`, writes serialised so GATT operations never overlap).
- **Known differences between the clients** (not bugs in our code): text in the four FreeType-sensitive fonts differs by about a dot (FreeType 2.13 vs 2.15), and a picture that needs a resize to a non-square size can dither differently, because Pyodide's Pillow (12.2) resamples differently from Pillow 13.0 (the browser equals Node-Pyodide exactly; same Pillow version on both sides gives identical dots). Everything else has been checked bit for bit.
- Pictures keep the name they were chosen with inside the stored file name (`<hash>-<name>.png`; the page shows it without the hash), so a saved label can show it. Pictures: a client writes the bytes where the engine can read them and calls `api.adopt_image(path, name)` (checks, size cap, content-hash name under the temp folder); the label then carries that path in `image_path`. Don't add per-client picture code.
- Keep `api.py` plain data in and out; the UI must never need to know about Pillow or `LabelSpec`. Run it: `python src/dotlab/web/dev_server.py`, then http://localhost:8000. A phone reaches it with `adb reverse tcp:8000 tcp:8000` (Web Bluetooth needs https or localhost).
- Verified (2026-10): the browser build printed over Web Bluetooth from Android Chrome; the browser's pixels equal the native engine's byte for byte except the four FreeType-sensitive fonts (see the layout pin above), where they equal Node-Pyodide's. Chromium on Linux can't use Web Bluetooth with this printer (BlueZ), so test BLE from a phone. Web Serial over classic Bluetooth (`printer/serial.js`, the Serial Port service, 9600 baud is ignored) is verified on Linux Chromium 156 (2026-11): the printer must be paired in the OS once, then the browser lists it; a link left over from a killed browser blocks the next open until `bluetoothctl disconnect <addr>`. `printer/index.js` offers BLE where `navigator.bluetooth` exists and serial where `navigator.serial` does; with both, the choice is remembered. Serial is untested on Windows/macOS.

## Hardware facts (found by calibration — don't re-derive)

- The vendor's CUPS driver (from the USB stick in the box) is analysed in `docs/vendor-driver.md`: its exact TSPL command stream, the `DENSITY 0..30` range, and the `REFERENCE`/`OFFSET`/`SET TEAR|PEEL|CUTTER` lines it sends on every job that we don't (the best lead on the continuous-paper "Label error").

- USB `0483:5743` (no longer used by the app: Bluetooth is the only transport, for parity across platforms; the facts are kept for reference), TSPL, bulk OUT `0x01` / IN `0x82`. Kernel 7.x has no `usblp`; no CUPS needed. Device node is group `lp`, no sudo.
- 58 mm paper, **384 printable dots** wide at 203 dpi. Label pitch is 240 dots (`SIZE 72 mm,30 mm`, `GAP 2 mm`), but the sticker is only **224 dots** (`core.SH`) tall; anything below that falls in the gap and is lost.
- TSPL `BITMAP` mode 0: bit 1 = white, 0 = black (same as Pillow mode "1").
- Status query `ESC !?`: `0x00` ready, `0x20` printing; bit flags in `core.STATUS_FLAGS`.
- **Bluetooth (probed 2026-10; hardware facts: the page uses BLE via Web Bluetooth and RFCOMM via Web Serial).** Dual-mode, one public address (`T003-xxxx`), and the same TSPL goes over either transport unchanged (a test label printed correctly on both). RFCOMM needs **no pairing** (connecting with the address worked while BlueZ showed Paired/Bonded/Trusted: no):
  - *Classic SPP:* RFCOMM channel 1 (`socket.AF_BLUETOOTH`, `BTPROTO_RFCOMM`); `ESC !?` answers `00` (possibly after a stale leftover byte: drain after connecting). Sent in 512-byte chunks with a 20 ms gap (`bluetooth.RFCOMM_CHUNK` / `RFCOMM_GAP`). Needs Python's `AF_BLUETOOTH` sockets: Linux has them; macOS builds don't and Windows is untested, so `bluetooth._connect` says so instead of crashing.
  - *BLE (GATT):* write TSPL to `00002af1-…` (service `000018f0-…`, value handle `0x000b`, write + write-without-response); replies arrive as notifications on `00002af0-…` (`0x0008`). The ISSC UART (`49535343-8841-…` write, `0x0011`) also reaches the parser, and `bef8d6c9-…` (service `e7810a71-…`) gave no reply. Advertised service list differs from the real GATT database (`1800/180d/180f/fee7` advertised; `fee7` was not needed). Web Bluetooth from Android Chrome: **180-byte chunks, 5 ms gap** sends a whole label in ~0.6 s; 20 B/20 ms works but takes 16 s. Don't overlap writes (`GATT operation already in progress`).
  - *BlueZ on Linux can't open the BLE link:* `Device1.Connect` on a dual-mode device returns `BREDR.ProfileUnavailable: No more profiles to connect to` and drops the link, so Chromium and bleak fail (Android works). Only `btgatt-client -d <MAC> -t public` (direct L2CAP LE) got through; `bluetoothctl` has no usable `bearer`/`le` connect here. `ControllerMode = le` in `/etc/bluetooth/main.conf` would likely fix it but disables classic Bluetooth system-wide (untested). So on Linux use RFCOMM; a web app is for phones. (Removing the bond with `bluetoothctl remove` was needed to probe LE; RFCOMM works without it.)
- **Continuous (non-sticker) paper, probed 2026-11-05 — not supported, don't re-probe without a new idea.** The firmware answers ESC/POS-style status (`GS I D` = serial `T003-…`, `DLE EOT 1/2/4`) but no TSC settings queries (`~!T`, `GETSETTING$`, `~HS` all silent), so media size and gap mode can't be read back. A ~55-57 mm plain roll: `SIZE <w> mm,<h> mm` + `GAP 0 mm,0 mm` (or no `GAP` at all) prints correctly at 40 mm tall, the 384 dots (48 mm) sit centred with 2-4 mm of margin each side, and ~1.5 cm extra paper feeds afterwards. But the OLED then shows "Label error" after every job, with the printer's own label type set to Continuous; the feed button doesn't clear it, further jobs are ignored until a restart, and a 16 mm job (status `0x02` afterwards) left the printer unreachable over Bluetooth until restarted. `SIZE` width (72 vs 57 mm) made no difference. Cause unknown; the app stays on the sticker (`SIZE 72 mm,30 mm`, `GAP 2 mm`). New lead (2026-11-06, **not yet tried**): the vendor CUPS driver sends `REFERENCE 0,0`, `OFFSET 0.0 mm`, `SET RIBBON OFF` and `SET TEAR/PEEL/CUTTER ON|OFF` on every job and our probes sent none of them; see `docs/vendor-driver.md`. Also untested: `DENSITY` above 15 (the vendor code accepts 0..30).
- Each real print uses a sticker — prefer `--preview`/the GUI preview and tests over test prints.
